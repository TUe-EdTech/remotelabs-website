# production_source/ - Development Source

This folder is the **source of truth** for the website. Edit files here,
never in `deploy/` (that folder is generated by the build and by CI).

- `index.html` / `privacy.html` — pages. The `<style id="critical-css">`
  placeholder in the `<head>` of `index.html` is filled at build time with
  the marked critical section of `styles.css`; all other page styles live
  in `styles.css` (the single source of CSS)
- `styles.css` — full stylesheet (readable source; the build minifies it to
  `deploy/styles.min.css`)
- `script.js` — site interactions (loaded as `deploy/script.min.js`)
- `sw.js` — service worker (cache name synced from the root `VERSION` file)
- `build.js` — canonical build: `npm run build:full`
- `test.js` — consistency/security checks: `npm test`
- `check-render.js` — render smoke test: `npm run test:render` serves `../deploy/`
  and asserts in headless Chrome that the critical CSS and full stylesheet apply
  (guards against shipping an unstyled page)
- `assets/` — images, videos, fonts, publications, partner logos
- `package.json` — build/test tooling (`clean-css`, `uglify-js`, `chrome-launcher`,
  `chrome-remote-interface`)

## Workflow

```bash
cd production_source
npm install            # once
npm run build:full     # sync VERSION strings, minify, regenerate ../deploy/
npm test               # source + deploy/ + VERSION consistency
npm run test:render    # built pages render styled in headless Chrome
node ../scripts/check-links.js ../deploy   # link/asset integrity
```

Release ritual: bump the root `VERSION` (`node scripts/bump-version.js`
does PATCH + build in one step), run the build, commit **source and
`deploy/` together**.

See the root `README.md` for the project overview and `AGENTS.md` in this
folder for the detailed development guide (caching model, testing,
deployment, security).
